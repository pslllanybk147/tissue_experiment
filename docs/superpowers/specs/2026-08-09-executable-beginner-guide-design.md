# Executable Beginner Guide Design

## Goal

เปลี่ยนหน้าคู่มือจากรายการคำอธิบายที่ผู้ใช้ต้องตีความเอง ให้เป็นคำสั่งปฏิบัติทีละบรรทัดสำหรับมือใหม่ โดยเฉพาะขั้นฟอก/ล้างของ Violin ด่าง และรักษาความแตกต่างระหว่าง protocol หลักกับแขนทดลองไว้ชัดเจน

## User outcome

เมื่อผู้ใช้เปิดขั้นตอนหนึ่ง ผู้ใช้ต้องตอบได้ทันทีว่า:

- ตอนนี้ต้องทำอะไร
- ต้องใช้ของชิ้นไหนและปริมาณเท่าไร
- ต้องใส่ในภาชนะใด
- ต้องจับเวลากี่นาที
- จะรู้ได้อย่างไรว่าขั้นนี้เสร็จ
- ขั้นถัดไปคืออะไร

## Design

### 1. แยกคู่มืออธิบายออกจาก runner ที่ลงมือจริง

หน้าคู่มือสาธารณะยังคงอธิบายหลักการและหลักฐานได้ แต่ส่วน “ทำทีละข้อ” จะใช้โครงสร้างคำสั่งที่มี label ชัดเจน ไม่ใส่ทางเลือกหลายแบบรวมอยู่ในประโยคเดียว

สำหรับขั้นฆ่าเชื้อ ให้แสดง protocol ที่เลือกแล้วเท่านั้น เช่น Control-A, T1, T2 หรือ T3 ส่วน protocol อื่นย้ายไปอยู่ในส่วน “เปลี่ยนวิธีทดลอง” หรือรายละเอียดเพิ่มเติม

### 2. ใช้คำสั่งปฏิบัติแบบมี metadata

คำสั่งแต่ละข้อควรมีชนิดของงาน, เวลา, ภาชนะ, ปริมาณ, เกณฑ์เสร็จ และคำสั่งถัดไปได้ในอนาคต โครงสร้างข้อความเดิมยังรองรับขั้นอื่น แต่ขั้นที่มีรายละเอียดสูงจะเพิ่ม execution block เพื่อไม่บังคับให้ renderer เดาความหมายจากข้อความยาว

### 3. ผูกผลเครื่องคำนวณเข้ากับคำสั่ง

เครื่องคำนวณ Haiter/NaDCC ต้องแสดงผลในบริบทของขั้นตอน ไม่ใช่แค่ปุ่มเปิด overlay ผู้ใช้ต้องเห็นค่าที่ใช้จริง เช่น stock, working solution, ปริมาตรที่ต้องตวง, ปริมาตรรวม, จำนวนภาชนะ และความเข้มข้นที่ได้จริง

ห้าม hardcode ปริมาตรของ Haiter ที่เป็น `% w/w` เป็น mL โดยไม่มี density หรือการชั่งมวลรองรับ ระบบต้องบอกฐานของฉลากและใช้หน่วยที่สอดคล้องกัน

### 4. ออกแบบขั้นฆ่าเชื้อให้เป็นเส้นทางเดียว

เส้นทางหลักของแต่ละรอบต้องมีลำดับภาชนะที่ผู้ใช้ติดป้ายได้ เช่น `S`, `R1`, `R2`, `R3`, `F` และแสดงจำนวน/ปริมาตร/เวลาต่อภาชนะอย่างชัดเจน

คำว่า “น้ำ rinse” ต้องเขียนเป็น “น้ำล้างคลอรีนต่ำ 300 ppm (ไม่ใช่น้ำปลอดเชื้อ)” เมื่อเป็นแขนทดลอง และต้องไม่ปะปนกับ Control-A ที่ใช้น้ำปลอดเชื้อธรรมดา

### 5. จัดคำเตือนตามความเร่งด่วน

คำเตือนที่ต้องหยุดทันทีอยู่ใกล้การลงมือทำ คำเตือนก่อนเริ่มอยู่ใน preflight และรายละเอียดหลักฐาน/ความไม่แน่นอนอยู่ในส่วนขยาย ไม่แทรกประโยค “ถ้าไม่มั่นใจ...” ซ้ำในรายการหลัก

## Acceptance criteria

- ขั้นฟอกของ Violin ด่างแสดงคำสั่งเป็นข้อที่ทำตามได้ ไม่ใช่ย่อหน้าเงื่อนไขหลายทาง
- หน้าแสดง protocol ที่เลือก, ภาชนะ, ปริมาณ และเวลาที่เกี่ยวข้องกับรอบนั้น
- มี regression tests ป้องกันคำว่า `ประมาณ` หรือ placeholder ที่ทำให้ผู้ใช้ต้องเดาปริมาณ/เวลาในคำสั่งหลัก
- ขั้นที่ไม่มี execution metadata ยังคงแสดงได้ด้วยรายการข้อความเดิม
- layout อ่านได้บนมือถือและ desktop โดยไม่ทำให้ตาราง/ตัวเลขล้นจอ
- คำเตือนการผสมสารอันตรายยังคงแสดงก่อนคำสั่งลงมือทำ

## Out of scope for this pass

- ยืนยันค่าฟอกที่เหมาะที่สุดสำหรับ Violin ด่างจากงานวิจัยใหม่
- เปลี่ยนผลการทดลองหรือยกระดับค่าที่เป็น adapted/unsupported ให้เป็น species-direct
- สร้างระบบจับเวลาแบบ background หรือแจ้งเตือนบนโทรศัพท์เต็มรูปแบบ
