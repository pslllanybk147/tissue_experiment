# ระยะตั้งต้นแบบชุดสูตรเปรียบเทียบและหมายเหตุคำศัพท์

## บริบท

คู่มือบางชนิดมีสูตร `establishment` แต่ยังไม่มีงานวิจัยตรงระยะตั้งต้นจากชิ้นพืช ระบบจึงควรแสดง MS ไม่ใส่ PGR เป็นชุดควบคุมพร้อมตัวเลือกฮอร์โมนที่มาจากงานใกล้เคียง โดยไม่ทำให้ผู้ใช้เข้าใจว่าเป็นผลยืนยันตรงพันธุ์ นอกจากนี้ `RichText` ยังจับคำศัพท์อัตโนมัติทุกข้อความ ทำให้คำทั่วไปอย่าง “ข้อถัดไป” และ `ppm` ถูกแสดงเป็นปุ่มหมายเหตุซ้ำ ๆ

## เป้าหมาย

1. เพิ่มชุดสูตรเปรียบเทียบสำหรับระยะตั้งต้นที่ไม่มีหลักฐานตรงในแผ่นเสริมพืชที่มี `establishment` แบบ unsupported
2. ใช้ค่าตั้งต้นเดียวกันที่ตรวจสอบย้อนกลับได้: MS ไม่ใส่ PGR, MS + BA 0.5 mg/L และ MS + 6-BA (BAP) 1.0 mg/L + IBA 0.5 mg/L
3. ทำให้เครื่องคำนวณเลือกสูตรเหล่านี้ได้ ใช้ stock mapping เดิม และแสดงข้อจำกัด/หลักฐานของสูตรที่เลือก
4. ให้หมายเหตุคำศัพท์เกิดเฉพาะข้อความที่ผู้เขียนห่อด้วย `[[term-id|ข้อความ]]`
5. ป้องกันการกลับมาจับคำทั่วไปแบบอัตโนมัติด้วย unit tests และตรวจทุกจุดเรียก `RichText`

## ไม่อยู่ในขอบเขต

- ไม่ยกระดับสูตรใดเป็นหลักฐานตรงพันธุ์เพียงเพราะเพิ่มเข้าไปในรายการ
- ไม่เปลี่ยนสูตร multiplication หรือ rooting ที่มีอยู่แล้ว
- ไม่ลบทะเบียน contextual terms (`ppm`, `น้ำปลอดเชื้อ`, `น้ำยาแม่` ฯลฯ); เปลี่ยนเฉพาะวิธีเรียกใช้ในข้อความ
- ไม่ทำการทดลองจริงหรือสรุปว่าชุดใดดีที่สุด

## การออกแบบข้อมูลสูตร

เก็บ `id: "establishment"` เดิมไว้เป็นชุดควบคุมเพื่อไม่ทำลายการเลือกสูตรเริ่มต้นของขั้น `prep-media` และเพิ่มสองรายการใน `mediaRecipes` ของแต่ละแผ่นเสริมที่มีสูตรตั้งต้น unsupported:

- `establishment-ba`: ชื่อ “ระยะตั้งต้น · MS + BA (ชุดทดลอง)” และ BA 0.5 mg/L
- `establishment-bap-iba`: ชื่อ “ระยะตั้งต้น · MS + 6-BA (BAP) + IBA (ชุดทดลอง)” และ 6-BA (BAP) 1.0 mg/L กับ IBA 0.5 mg/L

ทั้งสามสูตรใช้ MS, sucrose, agar และ pH เดียวกับสูตรตั้งต้นของแผ่นเสริมนั้น สูตรควบคุมคง `unsupported` ตามเดิม ส่วนสองสูตรฮอร์โมนใช้ `adapted` พร้อม `sourceIds` ของงานใกล้เคียงที่มีอยู่ในทะเบียน และ `note` ระบุชัดว่าค่าความเข้มข้นเป็นจุดเริ่มคัดกรอง ไม่ใช่งานตรงระยะตั้งต้นของชนิดนั้น

รายการที่ต้องตรวจและแก้คือ Pink Princess, Violin Variegated, Thai Constellation, Scindapsus exotica, Rhaphidophora tetrasperma variegata และ Generic Philodendron เท่านั้น พืชที่ไม่มีขั้น `establishment` หรือมีงานตรง/สูตรเฉพาะระยะอื่นจะไม่ถูกเติมสูตรโดยอัตโนมัติ

## การเชื่อมกับเครื่องคำนวณ

`MediumCalculator` ใช้ `recipes` ทั้งรายการอยู่แล้ว จึงไม่ต้องสร้างเส้นทางคำนวณใหม่ เพิ่มเพียง:

- ยืนยันว่า `stockIdForIngredient` จับ `BA`, `BAP`, `6-BA (BAP)` และ `IBA` ตามชื่อสูตรใหม่
- แสดง `recipe.evidence.note` ใต้ป้ายระดับหลักฐาน เพื่อให้ข้อจำกัดของสูตรเห็นในจุดที่ผู้ใช้เลือกสูตร
- คงสูตร `establishment` เป็นค่าเริ่มต้นเมื่อเข้าขั้นตั้งต้น; ผู้ใช้เลือกชุดเปรียบเทียบจาก dropdown ได้
- เพิ่มเทสต์ว่าทุกแผ่นเสริมกลุ่มนี้มีสามสูตร, ปริมาณฮอร์โมนตรงตามสเปก และเครื่องคำนวณใช้ stock ที่ตรงตัวโดยไม่แทน BA/BAP กันเอง

## การออกแบบคำศัพท์และหมายเหตุ

เปลี่ยน `RichText` ให้แปลงเฉพาะ `parseTerms` (รูปแบบ `[[...]]`) เป็น `TermHelp` และแสดงข้อความส่วนที่เหลือเป็นข้อความธรรมดา ไม่เรียก `parseContextualTerms` ในเส้นทาง render ทั่วไปอีกต่อไป การห่อคำที่มีอยู่แล้วใน core steps, species, genera และ form จะทำงานเหมือนเดิม ส่วนข้อความธรรมดาอย่าง “ข้อถัดไป”, “ข้อควรระวัง” และ `ppm` จะไม่เกิดหมายเหตุเอง

คง `parseContextualTerms` ไว้เป็น utility ที่มีเทสต์เดิม เพื่อไม่ทำลายผู้เรียกภายนอกระหว่างการเปลี่ยนผ่าน แต่ไม่มี UI ใดเรียกมันอัตโนมัติ เพิ่มเทสต์ render โดยตรงว่า `RichText` ไม่สร้าง `<details>` ให้ข้อความทั่วไป และยังสร้าง `<details>` ให้ `[[node|ข้อ]]` / `[[ppm|ppm]]` เมื่อผู้เขียนระบุเจตนา

## การตรวจสอบ

1. เพิ่ม unit tests แบบ failing ก่อนแก้ implementation สำหรับสูตรและการ render คำศัพท์
2. รันเฉพาะเทสต์ที่เกี่ยวข้องจนผ่าน
3. รัน `npm test`, `npm run lint`, `npm run build`, `npm run protocol:verify`, `npm run ui:verify` และรายงานข้อจำกัดของสภาพแวดล้อมถ้ามี
4. ตรวจ diff และค้นซ้ำทั้ง repository ว่าไม่มี `RichText` เส้นทางใดเรียกตัวจับคำอัตโนมัติหรือมี recipe id ซ้ำในแผ่นเสริม
