# เฟส 3a · ภาพอ้างอิงของทรง

> ลงวันที่ 6 สิงหาคม 2026 · สถานะ **อนุมัติแล้ว รอเขียนแผน implementation**
>
> สเปกนี้เป็นครึ่งแรกของสิ่งที่ `2026-08-05-growth-form-first-redesign-design.md` เรียกว่าเฟส 3
> ครึ่งหลัง (รูปที่ผู้ใช้อัปเอง และเครื่องมือปักหมุดของผู้ใช้) แยกเป็นสเปกของตัวเองในชื่อ 3b

## 1 · ทำไมต้องแยก 3a ออกจาก 3b

สิ่งที่เดิมเรียกรวมกันว่า "เฟส 3" เป็นสองระบบที่แยกกันเกือบสมบูรณ์

| | 3a ภาพอ้างอิงของทรง | 3b รูปผู้ใช้และเครื่องมือปักหมุด |
|---|---|---|
| เกิดตอนไหน | ตอน build | ตอนใช้งาน |
| มี state ไหม | ไม่มี | มี |
| ต้องล็อกอินไหม | ไม่ต้อง | ต้อง |
| พึ่งอะไรที่ยังไม่ยืนยัน | ไม่มี | Firebase Auth ผู้ใช้จริง · Cloudinary · Firebase Admin |

`project_summary.md` ส่วนที่ 12 บันทึกไว้ตั้งแต่ก่อนงานรอบนี้ว่า **การอัปโหลดรูปยังไม่เคยทดสอบจริง**
การเริ่ม 3b ก่อนยืนยันว่าท่ออัปโหลดทำงาน คือการสร้างของทับบนฐานที่ยังไม่รู้ว่ามีอยู่จริง
3a จึงมาก่อน และมันยังเป็นตัวตอบว่า "หมุดหน้าตายังไงบนหน้าจอ" ซึ่ง 3b ต้องรู้ก่อนเริ่ม

## 2 · ปัญหาที่แก้

เจ้าของระบบระบุ painpoint ไว้ตรง ๆ ว่าภาพที่มีอยู่ **"เป็นภาพต้นจริง แต่ไม่รู้ตำแหน่งตัด"**
ตอนนี้ทั้งแปดทรงไม่มีภาพเลย ทุกหน้าทรงแสดงกล่องว่ายังไม่มีภาพอ้างอิง
ซึ่งซื่อสัตย์แต่ยังไม่ช่วยให้มือใหม่หาจุดสังเกตบนต้นจริงได้

---

## 3 · ขอบเขต

**หนึ่งทรง หนึ่งภาพ** ภาพเดียวมีหมุดของทุกจุดสังเกต รวมแปดภาพ

เหตุผลที่ไม่ใช่ภาพต่อจุด คือมือใหม่ต้องเห็นก่อนว่าจุดต่าง ๆ อยู่ตรงไหน**เทียบกัน**
ภาพแยกจุดทำให้ความสัมพันธ์เชิงตำแหน่งหายไป ซึ่งเป็นสิ่งเดียวที่ภาพให้ได้แต่ข้อความให้ไม่ได้

**ภาพของทรงคือภาพต้นจริงของชนิดหนึ่งที่เป็นตัวแทน** ไม่ใช่ภาพวาดและไม่ใช่ภาพของทุกชนิด
จึงต้องติดคำบรรยายบอกชนิดที่อยู่ในภาพเสมอ ตามกฎชั้น D ของ `newplant_protocol.md` ขั้นที่ 5

**ใบอนุญาต CC BY-SA 4.0** สอดคล้องกับขั้นที่ 5 ของโปรโตคอลที่เจ้าของระบบเขียนเอง
คือเรียกร้องให้แหล่งอื่นเปิดภาพ การเปิดของตัวเองจึงต้องสอดคล้องกัน

---

## 4 · สคีมา

`referenceImageId?: string` ไม่พอ เพราะภาพที่ commit ขึ้น public repo ต้องพกเครดิต ใบอนุญาต
และคำบรรยายสำหรับคนที่มองไม่เห็นภาพติดตัวไปด้วย

```ts
export type FormImage = {
  /** ไฟล์ใน public/forms/ */
  file: string;
  /** ชนิดที่อยู่ในภาพจริง ๆ บังคับ เพราะภาพของทรงคือภาพของชนิดหนึ่งที่เป็นตัวแทน
   *  ไม่ใช่ภาพของทุกชนิดในทรง ต้องบอกผู้ใช้ตรง ๆ */
  speciesShown: string;
  credit: string;
  license: "CC BY-SA 4.0";
  /** ต้องบรรยายโครงสร้างที่เห็น ไม่ใช่ "ภาพต้นไม้" */
  alt: string;
  /** ใช้กันหน้ากระตุกตอนโหลด และใช้คำนวณครอป */
  width: number;
  height: number;
};
```

`GrowthForm.referenceImage?: FormImage` แทน `referenceImageId?: string`

**`Landmark.point` ยังคง optional แม้ทรงมีภาพแล้ว** เพราะจุดสังเกตบางอย่างไม่ใช่ตำแหน่งบนต้น
เช่น "ด้านบนด้านล่างของชิ้นใบ" ในทรง `thick-leaf-no-stem` ซึ่งเป็นแนวคิดไม่ใช่ที่ที่ชี้ได้
การ์ดของจุดแบบนี้ไม่มีหมุดและไม่มีภาพซูม แต่ยังแสดงคำอธิบายตามปกติ

กฎเดิมที่ว่า **มีพิกัดได้เมื่อทรงมีภาพเท่านั้น** ยังคงอยู่ เปลี่ยนแค่ชื่อฟิลด์ที่ตรวจ

**การย้ายฟิลด์กระทบสามจุดเท่านั้น** คือ `forms/types.ts`, `forms/registry.test.ts` (เทสต์พิกัด)
และ `components/guide/form-detail.tsx` (กล่องบอกว่ายังไม่มีภาพ) เพราะ**ตอนนี้ยังไม่มีทรงใดตั้งค่า
`referenceImageId` ไว้เลย** จึงไม่มีข้อมูลให้ย้าย

## 5 · ไฟล์ภาพ

| ข้อกำหนด | ค่า |
|---|---|
| ที่อยู่ | `public/forms/<formId>.jpg` |
| ความกว้าง | ไม่เกิน 1400 px |
| รูปแบบ | JPEG |
| ขนาดเป้าหมาย | ไม่เกิน 250 KB ต่อใบ |

แปดใบรวมประมาณ 2 MB ใน repo ซึ่งรับได้ และไม่ต้องพึ่งบริการภายนอกที่ยังไม่ยืนยัน

## 6 · เครื่องมือปักหมุด `/admin/pin`

เลือกทรง แสดงภาพ คลิกบนภาพเพื่อเก็บพิกัด แล้วพิมพ์โค้ดให้คัดลอกไปวางในไฟล์ทรง

```ts
point: { x: 0.42, y: 0.31 },
```

**ทำไมต้องมี** รอบแรกมี 24 พิกัด และทุกครั้งที่เปลี่ยนภาพต้องแก้ใหม่ทั้งทรง
การเดาค่าแล้วรีเฟรชดูทีละจุดจะทำให้เลิกกลางคัน และเครื่องมือนี้เป็นต้นแบบของเครื่องมือปักหมุด
ที่ผู้ใช้จะใช้กับรูปตัวเองใน 3b

**ข้อยกเว้นที่บันทึกไว้ตรง ๆ** เฟส 1 ตั้งกฎว่าห้ามเพิ่ม client component ใหม่
หน้านี้ละเมิดกฎนั้นเพราะการรับพิกัดจากการคลิกต้องใช้ JavaScript จริง
**ยกเว้นเฉพาะโซน `/admin` ซึ่งไม่ใช่หน้าผู้ใช้** และต้องเขียนเหตุผลกำกับไว้ในไฟล์
หน้าสาธารณะทุกหน้ายังคงเป็น Server Component ล้วนตามเดิม

## 7 · หน้าทรงที่มีภาพ

```
┌──────────────────────────────────┐
│  [ ภาพต้นจริง เต็มความกว้าง ]     │
│      ①        ②                  │
│              ③                   │
└──────────────────────────────────┘
ภาพ: <speciesShown> · ถ่ายโดย <credit> · CC BY-SA 4.0
ใช้แสดงโครงสร้างของทรงนี้ ไม่ใช่ภาพของทุกชนิดในทรง

┌─────┬────────────────────────────┐
│[ซูม]│ ① ข้อ                       │
│ ①  │ คืออะไร · หายังไง · อย่าสับสน │
└─────┴────────────────────────────┘
```

หมุดวางตำแหน่งด้วยเปอร์เซ็นต์ จึงสเกลตามภาพเองโดยไม่ต้องใช้ JavaScript
การ์ดข้างล่างขึ้นต้นด้วยเลขเดียวกับหมุด และการ์ดที่มีพิกัดจะมีภาพซูมของจุดตัวเองอยู่ด้านซ้าย
โดยซูมมาจากภาพใบเดิม ไม่ต้องถ่ายเพิ่ม

**ทรงที่ยังไม่มีภาพแสดงผลเหมือนเดิมทุกอย่าง** กล่องบอกว่ายังไม่มีภาพยังอยู่
ไม่ต้องเขียนโค้ดสองทาง เพราะภาพเป็นส่วนเสริมที่วางทับโครงเดิม ไม่ได้แทนที่

### การคำนวณครอป

```ts
/** คืนค่า background ที่ทำให้จุด point อยู่กลางช่องซูมพอดี */
export function cropStyle(
  point: { x: number; y: number },
  swatchPx?: number,
  zoom?: number,
): { backgroundSize: string; backgroundPosition: string };
```

ค่าเริ่มต้น `swatchPx = 72` และ `zoom = 3`

**เหตุผลที่ไม่ใช้ `background-position: 42% 31%` ตรง ๆ** เปอร์เซ็นต์ของ CSS จัดให้จุด 42% ของภาพ
ไปตรงกับจุด 42% ของกรอบ ซึ่งไม่ใช่การวางจุดนั้นไว้กลางกรอบ จุดที่อยู่ริมภาพจะเพี้ยนหนักที่สุด
คำนวณเป็นพิกเซลแล้วปล่อยออกมาเป็น inline style ได้ค่าที่ตรง และทดสอบได้เพราะเป็นฟังก์ชันบริสุทธิ์

## 8 · การทดสอบ

คงแนวเดิมทั้งหมด `renderToStaticMarkup` ไม่มี jsdom ตรรกะเป็นฟังก์ชันบริสุทธิ์แยกจาก React

**กฎที่บังคับด้วยเทสต์ ห้ามแก้เทสต์เพื่อให้ผ่าน**

| กฎ | เหตุผล |
|---|---|
| ทุก `file` ที่อ้าง ต้องมีไฟล์จริงใน `public/forms/` | แบบเดียวกับกฎ `illustrationId` เดิม |
| `alt` ต้องยาวเกิน 20 ตัวอักษร | กัน `alt="รูป"` ซึ่งแย่กว่าไม่มี alt |
| `speciesShown` และ `credit` ห้ามว่าง | ภาพขึ้น public repo ต้องบอกที่มาได้เสมอ |
| `license` ต้องเป็น `"CC BY-SA 4.0"` เท่านั้น | กันภาพใบอนุญาตปิดหลุดเข้ามา |
| `point` ต้องอยู่ในช่วง 0 ถึง 1 | พิกัดหลุดกรอบทำให้หมุดลอยนอกภาพ |
| มีพิกัดได้เมื่อทรงมีภาพเท่านั้น | กฎเดิม เปลี่ยนแค่ชื่อฟิลด์ที่ตรวจ |
| `cropStyle` วางจุดไว้กลางกรอบจริง รวมถึงจุดที่ริมภาพ | ตรรกะที่ผิดแล้วดูไม่ออกด้วยตา |
| หน้าทรงที่มีภาพต้องเรนเดอร์หมุดครบทุกจุดที่มีพิกัด | กันหมุดหายเงียบ |

**ต้องตรวจของจริงในเบราว์เซอร์ด้วย** อย่างน้อยหนึ่งทรงที่มีภาพจริง ทั้งโหมดสว่างและมืด
เพราะสามรอบที่ผ่านมาพบข้อบกพร่องที่เทสต์จับไม่ได้ทุกรอบ

## 9 · ความเสี่ยง

**หมุดชิดกันบนจอมือถือ** ถ้าจุดสังเกตสองจุดอยู่ใกล้กันในภาพ หมุดจะทับกันที่ความกว้าง 360px
บรรเทาด้วยการให้เลขหมุดเป็นตัวเชื่อมหลัก ผู้ใช้อ่านคำอธิบายจากการ์ดข้างล่างได้เสมอ
ถ้าเจอจริงตอนถ่ายภาพ ให้เลือกมุมถ่ายที่จุดต่าง ๆ กระจายตัวมากขึ้น แก้ที่ภาพดีกว่าแก้ที่โค้ด

**ภาพผูกกับพิกัดแน่น** เปลี่ยนภาพครั้งเดียวต้องปักหมุดใหม่ทั้งทรง เป็นเหตุผลที่ต้องมีเครื่องมือในส่วนที่ 6

**ยังไม่มีภาพสักใบตอนเริ่ม** งานโค้ดทั้งหมดของเฟสนี้ทดสอบได้ด้วยภาพตัวอย่างหนึ่งใบ
ไม่ต้องรอครบแปดใบ ทรงที่เหลือทยอยเติมได้เมื่อเจ้าของระบบถ่ายเสร็จ
