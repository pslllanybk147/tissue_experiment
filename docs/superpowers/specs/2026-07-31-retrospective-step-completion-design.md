# Retrospective Step Completion — Design

## เป้าหมาย

ผู้ใช้ต้องบันทึกงานที่ทำจริงก่อนเปิด Protocol v2 ได้โดยไม่ต้องทำซ้ำ และระบบต้องแยกข้อมูลย้อนหลังออกจาก Timer ที่เริ่มผ่านระบบอย่างโปร่งใส

## ขอบเขต

- ใช้กับทุกขั้นของ Protocol v2
- ไม่แก้หรือลบประวัติ Lot เดิม
- ไม่บังคับแนบรูป
- ไม่อนุญาตให้ข้ามขั้นโดยไม่มีข้อมูลยืนยัน
- Published Protocol ไม่ถูกแก้ไข ฟีเจอร์นี้เปลี่ยนเฉพาะ Step Run ของ Lot

## ประสบการณ์ผู้ใช้

ทุกขั้นแสดงปุ่มรอง `ฉันทำขั้นนี้ไว้แล้ว`

เมื่อกด ระบบเปิดส่วนบันทึกย้อนหลังในหน้าเดิม:

1. ผู้ใช้กรอกวันและเวลาที่เริ่มทำจริง
2. สำหรับขั้นที่ไม่มี Timer ผู้ใช้กรอกวันและเวลาที่ทำเสร็จ
3. สำหรับขั้นที่มี Timer ระบบคำนวณเวลาสิ้นสุดจากเวลาเริ่มจริงกับระยะเวลาของขั้น
4. ผู้ใช้ยืนยัน checklist และกรอกค่าที่บังคับเหมือนการทำแบบปัจจุบัน
5. ผู้ใช้เขียนหมายเหตุสั้นว่าทำอะไรและพบอะไร
6. ระบบแสดงผลก่อนบันทึก:
   - ถ้าครบเวลาแล้ว: บันทึกผ่านย้อนหลังและเปิดขั้นถัดไป
   - ถ้ายังไม่ครบเวลา: บันทึกเวลาเริ่มย้อนหลังและนับเฉพาะเวลาที่เหลือ
   - ถ้าเวลาเริ่มอยู่ในอนาคตหรือข้อมูลบังคับไม่ครบ: ไม่ให้บันทึกและบอกจุดที่ต้องแก้

## โครงสร้างข้อมูล

ขยาย `ProtocolStepRun`:

- `completionMode?: "live" | "retrospective"`
- `retrospectiveRecordedAt?: string`
- ใช้ `timerStartedAt`, `timerEndsAt` และ `completedAt` เดิมสำหรับเวลาที่ผู้ใช้ระบุ
- `observedAt` คือเวลาที่บันทึกข้อมูลเข้าระบบ

รายการย้อนหลังต้องแสดงใน audit/ประวัติว่า `บันทึกย้อนหลัง` และไม่แสดงว่า Timer ถูกเริ่มจากระบบ

## กฎการตรวจ

- วัน–เวลาเริ่มต้องไม่อยู่ในอนาคต
- เวลาสิ้นสุดต้องไม่น้อยกว่าเวลาเริ่ม
- ขั้น Timer ผ่านได้เมื่อเวลาปัจจุบันไม่น้อยกว่า `timerEndsAt`
- checklist และ measurement ที่บังคับยังต้องครบ
- การบันทึกย้อนหลังไม่เปลี่ยนจำนวนขั้นหรือปลดล็อกข้ามขั้น
- ขั้นถัดไปเปิดเฉพาะเมื่อ Step Run ก่อนหน้ามีสถานะ `Passed`

## การรองรับ Lot ปัจจุบัน

Lot v2 ที่มีอยู่แล้วใช้ฟีเจอร์ได้ทันที ไม่ต้องสร้าง Lot ใหม่ ผู้ใช้เปิดขั้น Blank 48 ชั่วโมง กด `ฉันทำขั้นนี้ไว้แล้ว` ใส่เวลาเริ่มเดิม และระบบคำนวณว่าครบหรือเหลือเวลาเท่าไร

## การทดสอบ

- ขั้นไม่มี Timer บันทึกย้อนหลังและเปิดขั้นถัดไป
- Blank 48 ชั่วโมงที่เริ่มเกิน 48 ชั่วโมงแล้วผ่านได้ทันที
- Blank ที่เริ่มไม่ครบ 48 ชั่วโมงแสดงเวลาที่เหลือและยังไม่ผ่าน
- ปฏิเสธเวลาในอนาคต
- ปฏิเสธ checklist หรือ measurement ที่ไม่ครบ
- reload แล้วยังคงเวลาและโหมดย้อนหลัง
- Firestore ตัด optional `undefined` และอ่าน field ใหม่กลับได้
- UI mobile/desktop ไม่ล้นและปุ่มมี focus state

## ข้อจำกัด

ระบบเชื่อข้อมูลย้อนหลังที่ผู้ใช้กรอกและระบุใน audit อย่างชัดเจนว่าเป็น self-reported data ระบบไม่อ้างว่าได้จับเวลาตั้งแต่เหตุการณ์จริง
